# Engineering notes

## Matching and evidence

The typed schema represents OR branches as a list of rules. Inside each rule, an exact model or explicitly supported alias must match, and any date-code or serial restrictions apply to that group together. Trimming external whitespace and folding case are the only identifier normalizations. Original values remain strings. Secura's two code sets stay with their respective models. Serial endpoints are inclusive, with a shared prefix and width. A serial outside that representation is unresolved. Sale windows are contextual fields in the stored source.

The source client requests the documented CPSC API by recall number and fetches the catalogued CPSC HTML page. It checks both identities and normalized descriptions, limits bytes and redirects, and uses a bounded request lifetime. The three recorded HTTP responses back the normalized review text via separate API and HTML hashes. Insignia's API record contains a literal space in the canonical URL slug. The client recognizes that exact metadata string, then independently fetches the listed canonical page. It follows redirects only on validated CPSC origins and paths. [CPSC API guide](https://www.cpsc.gov/Recalls/CPSC-Recalls-Application-Program-Interface-API-Information)

The review contract requires the normalized text hash of a reviewed source. The hash covers the full Recall Details text, including unfamiliar sections and unheaded additions. A small grammar reads the matching description and provides independently checkable rules. Each extraction needs the same criteria and uniquely locatable evidence for each group. Offsets address Python characters in the stored normalized text. Normalization collapses whitespace and retains wording and punctuation. Generated explanation wording is accepted only when it is permitted for the corresponding validated facts. Unexpected source content stays data and receives no tool authority.

## Uncertainty and persistence

A finding is one of `affected_by_notice`, `excluded_by_notice`, or `needs_information`. Exclusion requires a complete reviewed list or a supported identifier that falls outside a model's explicit conditions. The inventory summary prioritizes a confirmed affected finding, then relevant uncertainty, then supported exclusions. Outside-brand coverage is still displayed in the notice-level record. If there are no applicable findings, the inventory summary stays unresolved.

SQLite application tables retain uploads, snapshot versions, criteria, findings, events, questions, answers, and drafts. A separate LangGraph SQLite database carries the interrupted thread. A SQLite write lock serializes graph advances across local processes. Unique keys and UPSERTs make repeated submissions and graph-node replays idempotent. The answer is committed before the graph resumes. A restart can pick up the same interruption, and a repeated answer can recover a saved answer whose earlier resume was interrupted. Repeating with a different value returns a conflict. On successful source refresh with a new version, prior live findings become unresolved, with their historical evidence still marked as superseded. The finding write transaction also checks the current live hash so an interrupted investigation cannot publish findings from superseded coverage. The refresh audit records failed attempts separately.

The live adapter uses the official OpenAI SDK's Responses API and structured outputs. It restricts model inputs to the public notice or approved explanation wording, reserves estimated spend per attempt, and handles missing credentials, refusal, schema failure and budget exhaustion. Fixture mode reads the explicit payload files under `data/scripted`. [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) · [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)

## Evaluation design

`eval/gold_rules.json` and `eval/scenarios.csv` were committed before the extraction prompt. Insignia is the held-out notice. The labels, requests, and expected citation fragments were specified independently of the matcher. The `source_condition` cells simulate incomplete, unsupported, and conflicting scope. They are stress scenarios, with no claim that the official notices have those problems. The serial-range test also uses a synthetic rule. Scoring compares raw extraction fields against gold before grounding, then scores downstream affected recall and precision, exclusion errors, model matches, citations and requests. The evaluation counts only case-level evidence with an independently annotated fragment. Live measurements require an OpenAI key.

## Five interview questions

1. **Why does Secura need more than model lookup?** The same notice assigns different codes to two models and their aliases. `recall/criteria.py` puts each model and code set in its own branch. Comparing all models and codes independently would incorrectly affect a SAF-53D unit coded 1903.
2. **Why validate the rule if the quote is exact?** A real quote can mention an unrelated model or sale window. The validator requires both the full reviewed group semantics and evidence containing that group's supported wording.
3. **How does the agent decide to ask a question?** After looking up inventory, a route inspects unresolved findings for a specific missing or invalid field. It asks for that field on one unit and persists the interrupt. A run with only complete findings reaches the finish state.
4. **What happens if the source changes or an answer is submitted twice?** A changed hash preserves the previous snapshot and invalidates its live findings. A failed refresh records the failure separately. Identical answer submissions reuse the existing request, and a different answer is rejected as a conflict.
5. **How did you evaluate live model behavior?** The evaluation command measures raw extraction against independent labels, then runs the 60 cases using only validated criteria. The recorded run exercised deterministic matching and scripted extraction, and it verified fresh CPSC retrieval. The live model path remains unmeasured because the run environment had no API key.
